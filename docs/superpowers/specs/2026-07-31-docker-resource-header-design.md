# Docker 资源列表标题统一设计

日期：2026-07-31

## 目标

统一 Docker 的容器、镜像、卷、网络四个分段的列表操作入口，移除顶部导航栏的独立添加按钮，让用户在当前资源分段的列表标题行完成创建或维护操作。

## 交互与布局

- Docker 顶部导航栏保留终端入口，移除独立的 `+`。
- 每个资源分段的搜索框前使用同一标题行：左侧显示“共 N 个容器/镜像/卷/网络”，右侧显示 44pt 最小命中区的 `…` 菜单按钮。
- 菜单内容固定为：
  - 容器：创建容器。
  - 镜像：拉取镜像、清理悬空镜像。
  - 卷：创建卷。
  - 网络：创建网络。
- 继续使用既有 `OperationSheet` 和 `DockerOperationsModel`：本改动只改变入口位置，不能新增任何直接写 DockerService 的路径。
- Docker 不可用或存在写操作时，菜单沿用现有 gate 禁用；列表、搜索及导航保持可读。

## 实现边界

- 提取可复用的资源列表标题组件，四个分段只传入数量文案与菜单内容；不得分别复制四套布局。
- 容器标题行补齐现有镜像已有的资源数量与更多菜单；镜像、卷、网络转为相同组件。
- 用户可见文案继续走 `L()` 与现有 catalog，不新增操作语义。

## 验收

1. 顶部导航栏不再出现 Docker 添加按钮。
2. 四个分段均显示资源数量和右侧 `…` 菜单。
3. 每个菜单只包含本设计规定的操作，且仍走现有 sheet / 确认流程。
4. Docker 不可用或写操作进行中，菜单不可触发；列表仍可浏览。
5. Docker 模型/路由测试和 iOS Debug 构建通过。
