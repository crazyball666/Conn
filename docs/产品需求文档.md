## 1. 产品概述

### 1.1 一句话定位

**「把服务器装进口袋」**：一款面向开发者与运维人员的**纯客户端** iOS 应用，以 SSH 连接为核心，覆盖「连接 → 观测 → 处置」的移动运维闭环。无自建服务端、无账号体系，密钥与数据永远只在用户设备上——不只是一个终端，而是日常巡检与应急处置的移动工作台。

### 1.2 背景与机会

移动端 SSH/运维工具是一个**小而刚需、付费意愿高**的专业垂类：头部产品 Termius 自称服务超 100 万工程师，美区 App Store 开发者工具榜第 11 名、1.9 万条评分，Android 端约 360 万下载。2025–2026 年这个赛道出现三个明确的结构性机会：

1. **价格与商业模式的民怨**：Termius Pro 约 $119/年，差评高频词是 "insanely overpriced"；Blink Shell 从 $19.99 买断改为订阅后评分跌至 3.1★。「买断制/低价 + 慷慨免费版」成为被验证的口碑武器（WebSSH $4.5 买断、Secure ShellFish $29.99 终身均获 4.7★+）。
2. **"连接"和"观测"是割裂的，云端化还引发隐私反弹**：Termius 强在终端、弱在监控；ServerCat 强在监控、弱在处置闭环；同时社区对"强制账号/云同步"有明确的隐私顾虑（V2EX 有专帖寻找无云同步的客户端）。市场缺一个**纯本地**的「看状态 + 一键处置」移动工作台。（告警推送必须依赖服务端且有信任成本，本产品明确不做，取舍理由见 §4.1。）
3. **AI 成为品类标配变量**：Termius 推出 DevOps 智能体 Gloria，WebSSH 上线端侧 AI，新玩家 TermAI 以 $2.99/月低价 AI 订阅切入——自然语言生成命令、解释报错在手机场景（打字成本高）价值被放大。

### 1.3 产品愿景与目标

- **愿景**：成为开发者手机上的"服务器遥控器"——收到告警（来自你现有的监控体系）后，从看到通知到解决问题，全程不需要打开电脑。
- **一年目标**（上线后 12 个月，参照 §2.1 品类天花板校准）：
  - App Store 开发者工具分类国区进前 30、美区进前 100；
  - 累计添加主机 ≥ 10 万台，免费→付费转化率 ≥ 5%；
  - 买断退款率 < 2%，App Store 评分 ≥ 4.7。

### 1.4 核心设计原则

1. **应急优先（On-call first）**：所有高频应急操作（看状态、查日志、重启服务）3 次点击内可达。
2. **观测先于操作**：打开 App 第一眼看到的是服务器健康状态，而不是连接列表。
3. **安全默认开启、数据永不出设备**：私钥进 Secure Enclave、生物识别解锁、危险命令二次确认，默认全开；无服务端、无账号、零遥测。
4. **移动原生而非桌面移植**：为触屏、单手、碎片时间设计；终端体验必须补齐移动端输入短板。
5. **免费可用、买断更强**：单机免费完整可用，靠多机、Compose/服务管理、批量执行、同步等专业能力做一次性买断变现，不做订阅。

## 2. 市场调研

### 2.1 市场规模与用户群体

品类没有公开的权威市场规模数据，以头部产品代理指标估算天花板：

| 代理指标 | 数据 | 来源 |
|---|---|---|
| Termius 用户规模 | 官网自称 100 万+ 工程师；Android 约 360 万下载 | termius.com / AppBrain |
| Termius 美区 App Store | 4.7★、约 1.9 万评分，开发者工具榜 #11 | App Store |
| 第二梯队规模 | Secure ShellFish 1.4K 评分、WebSSH 700+、Blink 412（与头部差一个数量级） | App Store |
| 参照人群 | 全球专业开发者约 3000 万+，其中后端/DevOps/SRE 及自托管玩家为核心目标 | Stack Overflow 调查等 |

**用户群体**：① DevOps/SRE/系统管理员（on-call 应急）；② 独立开发者/个人站长（VPS 管理）；③ 自托管/Homelab 玩家（r/selfhosted 高频话题，NAS/树莓派）；④ 学生与 Linux 学习者。

**结构判断**：这是典型的"小市场、高转化"工具赛道——总量不大，但用户专业、付费能力强、需求刚性（服务器挂了必须处理），且头部产品的定价策略正在把价格敏感用户推向替代品。

### 2.2 核心使用场景调研

综合 Hacker News、Reddit（r/sysadmin、r/devops、r/selfhosted）社区讨论，移动运维的真实需求高度收敛：

**高频刚需（产品必须做透）**
1. **On-call 应急"三板斧"**：收到告警 → 手机看日志/指标确认严重程度（分诊 triage）→ 重启服务/回滚/扩容。社区共识：手机适合分诊和轻处置，重大变更回电脑。
2. **碎片时间巡检**：通勤/出差时瞄一眼 CPU、内存、磁盘、容器状态——这是 ServerCat 等监控类 App 的核心留存场景。
3. **预设一键操作**：把"重启服务、部署、清日志"做成片段/Widget 一键执行，比裸终端敲命令更符合手机交互。
4. **弱网续命**：高级用户的标准组合是 Blink + Mosh + tmux + Tailscale，证明"网络切换/锁屏不丢会话"是硬需求。

**伪需求（明确不做/降级）**
- 在手机上长时间编写复杂配置、做大规模变更——小屏易错，社区普遍反对，不应作为设计目标。

**设计结论**：产品围绕「**看 → 确认 → 一键动作**」设计，而不是复刻桌面终端。终端是兜底能力，仪表盘和快捷动作才是高频入口。

把海内外主要玩家放到「移动运维闭环」的能力矩阵上（●强 ◐弱 ○无）：

| 能力 | Termius | Blink | ShellFish | WebSSH | ServerCat | NeoServer | 阿里云App | **本产品目标** |
|---|---|---|---|---|---|---|---|---|

| 告警推送闭环 | ○ | ○ | ○ | ○ | ○ | ◐ | ●(仅本云) | ○（主动取舍，见 §4.1） |
| Docker 管理 | ○ | ○ | ○ | ○ | ◐ | ● | ○ | ● |
| AI 辅助 | ●(贵) | ○ | ○ | ◐ | ○ | ◐ | ◐ | ● |
| 断线续存(Mosh/tmux) | ◐ | ● | ◐ | ○ | ○ | ● | ○ | ● |
| 中文/国内生态 | ○ | ○ | ○ | ○ | ◐ | ◐ | ● | ● |
| 定价口碑 | 差 | 差 | 好 | 好 | 好 | 好 | 免费 | 目标：好 |

**三个结论**：

1. **没有任何一家同时做好「连接 + 监控 + 告警 + 处置」**。最接近的是 NeoServer（体量小、无服务端告警/拨测/第三方告警接入）和阿里云 App（绑定单云、终端差）。“移动运维工作台”这个位置仍然空着。（其中「告警推送」环节因依赖服务端，本产品主动取舍不做——理由见 §4.1，聚焦做透其余三个环节。）
2. **头部的用户不满是可收割的**：Termius/Blink 的订阅民怨 + Prompt 3 的后台断连差评，指明了「诚意定价 + 诚实的会话续存方案」两条获客路径。
3. **中国市场是结构性洼地**：海外竞品无一做国内生态（云厂商导入、宝塔/1Panel、人民币买断、国区上架），而国产竞品尚无一家完成告警闭环 + 生态整合。首发主打中文市场、同步上线英文版是合理路径。

4. **「服务与编排」维度全行业空白**：2026-07 对 8 款竞品逐项核实（附录 12.1）显示——Docker Compose 编排、定时任务管理无一家支持，systemd 服务管理仅 ServerBox 一家，历史监控曲线无人做。Conn 的「Docker + 日志 + 处置」路线正打在这片空白上。

## 4. 产品定位与差异化策略

### 4.1 定位

不做"又一个 SSH 终端"，做**「移动运维工作台」**：

```
          纯终端工具                     Conn                      重平台
  ┌─────────────────────┬──────────────────────────────┬─────────────────────┐
  │ Blink / WebSSH      │  连接 + 观测 + 处置 一体      │ 阿里云App / Grafana │
  │ 只解决"连上去"       │  解决"出事了怎么在手机上搞定" │ 只看不能操作/绑定单云 │
  └─────────────────────┴──────────────────────────────┴─────────────────────┘
```

**定位取舍（明确不做）**：不自建任何服务端——不做 7×24 告警推送、云端拨测、账号体系。理由：① 告警类云服务要求用户把服务器信息托管给第三方（即便无密钥的拨测/Agent 也有信任与合规成本），与「纯本地、零上传」的核心信任卖点冲突；② 服务端带来持续成本，会倒逼订阅制，而订阅正是本品类差评的第一来源。实时告警交给用户已有体系（云厂商监控/Grafana/宝塔/Bark 等），本产品专注承接**告警响起之后**的「看状态 + 一键处置」环节。

### 4.2 差异化抓手（对照竞品空白）

| # | 差异化抓手 | 打谁的痛点 | 依据 |
|---|---|---|---|
| 1 | **前台监控 + 一键处置闭环**：打开 App 即见全部主机健康状态，异常直达终端/片段/重启动作 | Termius 无监控；云厂商 App 终端差、绑定单云 | §2.3/§2.5 |
| 2 | **纯本地零上传**：无服务端、无账号、零遥测；同步仅走用户自己的 iCloud（端到端加密） | 云同步隐私顾虑（V2EX 专帖）；Termius 强制账号 | §2.4 |
| 3 | **诚意定价**：真实可用的免费版 + 百元内一次性买断，无订阅 | Termius $119/年民怨、Blink 转订阅崩盘；WebSSH/ShellFish 靠买断拿 4.7★+ | §2.3 |
| 4 | **移动原生输入体验**：加速键条、智能补全、片段变量、AI 生成命令（BYOK） | 手机打字成本高是全品类第一体验痛点，AI 恰好放大价值 | §2.2/§2.3 |
| 5 | **诚实的会话续存**：Mosh/tmux 恢复向导，不做定位保活 hack | Prompt 3 后台断连差评第一；Blink geo 保活耗电挨骂 | §2.3 技术调研 |
| 6 | **中文市场本地化**：中文体验、国内云生态（阿里云/腾讯云导入、宝塔/1Panel 识别）、人民币买断 | 海外竞品普遍无国内生态适配（详见 §2.4） | §2.4 |

**一句话策略**：不和 Termius 拼云服务和团队协作，用「纯本地 + 监控处置 + 买断」在隐私、价格、移动体验这三个它最弱、用户最不满的点上建立根据地。

## 7. 技术方案建议

> 纯客户端架构，无任何自建服务端——技术栈全部在 App 内闭环，你的 Swift 经验完全覆盖。

| 层 | 选型建议 | 说明 |
|---|---|---|
| UI | SwiftUI 为主 + UIKit 桥接终端视图 | 终端/编辑器等重交互区用 UIKit 包装 |
| 终端模拟 | **SwiftTerm**（开源，Miguel de Icaza） | La Terminal/Secure ShellFish 同款，成熟度最高 |
| SSH 协议 | **Citadel（基于 SwiftNIO SSH）** 优先；libssh2/NMSSH 兜底 | 纯 Swift、并发友好；注意补齐算法支持（如 ssh-rsa 兼容旧机器） |
| SFTP | Citadel SFTP / libssh2 | 断点续传自行封装 |
| 监控采集 | SSH 执行采集脚本（读 /proc 等），全部在 App 内完成 | 零安装、零上传；ServerCat 同模式，被市场验证 |
| 同步 | CloudKit（端到端加密封装后存储，走用户自己的 iCloud） | 免账号体系与服务器成本；导出恢复码防丢失 |
| AI | BYOK：用户自带 API Key，App 直连大模型官方接口，流式返回 | Key 仅存本机 Keychain；零服务器成本与合规负担 |
| 后台限制应对 | 会话后台 ~30s 宽限 + 断线自动重连 + tmux 恢复；BGAppRefresh 尽力巡检 + 本地通知 | 不做定位保活等擦边手段；产品内明示无实时告警 |

## 8. 商业化设计

### 8.1 定价原则（来自调研的强约束）

1. **免费版必须真实可用**（竞品免费版阉割是差评第一来源）——单机场景完整体验。
2. **买断制、不做订阅**：无服务端即无持续边际成本，订阅缺乏正当性；买断是国区强偏好（¥30–198 被广泛接受），也是海外市场的口碑武器（WebSSH/ShellFish 靠买断拿 4.7★+，Blink 转订阅评分崩至 3.1★）。
3. **国区独立锚点**：百元内买断；美区对标 ShellFish 终身档（$29.99）以下。
4. **AI 走 BYOK 且免费**：不产生服务器成本就不收费，作为免费版的光环功能拉口碑。

#### 逐家总评与 Conn 的对位策略

- **Termius**（美区 4.7★）：连接协议最全，免费档近年放开（SFTP/Face ID/FIDO2 已免费），但无监控/Docker、同步必须订阅、无中文。→ Conn 不拼协议广度，拼「监控 + Docker + 日志」纵深与买断价格。
- **Blink**（3.1★）：极客向最强终端（开源可自编译），转订阅后口碑崩盘、无 Shortcuts。→ 其流失用户是 Conn 买断制的目标人群。
- **Prompt 3**（4.3★）：体验精致、一次购买多端通用，但纯终端无 SFTP/监控，更新最慢（上次 2026-04）。→ 用功能纵深超越。
- **Secure ShellFish**（4.8★）：Files 挂载 + tmux + Shortcuts 生态整合独一档、更新极勤，但无监控、无中文。→ Conn 在 v1.1 补齐 Files/tmux 后以监控差异化。
- **WebSSH**（4.7★）：买断便宜、工具箱丰富、有中文，但无 Agent 转发/远程转发/FIDO2，国区未上架。→ 国区空位直接可取。
- **ServerCat**（4.6★）：免费监控中文友好，但免费版无终端、无 SFTP、无端口转发，连接能力最弱。→ Conn 免费版"终端不阉割"直接对打。
- **NeoServer**（4.8★/国区 4.9★）：**最直接的对标**——终端+SFTP+监控+Docker 一体、Mosh/tmux、中文佳；但闭源、文档少、免费版限制不透明。→ Conn 胜负手：日志中心、演示模式、中文输入法打磨等体验细节 + 免费版透明诚意 + 隐私白皮书的信息透明。
- **ServerBox**（4.9★，免费开源）：监控+Docker+systemd 全免费，封锁零付费人群；但 SSH 栈浅（无 Mosh/Agent 转发/Secure Enclave）、有稳定性差评。→ 免费版之战是体验之战不是功能之战：Conn 免费版必须比它稳、比它顺手。

**矩阵级结论**：① 终端强者（Termius/Blink/Prompt）监控为零，监控强者（ServerCat/ServerBox）连接弱或收费，全场景一体化只有 NeoServer 一家在做；② Compose、定时任务、历史曲线、systemd（除 ServerBox）是**全行业空白带**，即 Conn v1.5 的主攻方向；③ 头部产品全部保持月更节奏——上线后的持续更新能力是生存线，需在资源规划中预留。
