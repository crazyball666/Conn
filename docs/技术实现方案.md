## 1. 总体架构

### 1.1 分层与模块划分

采用 **SwiftUI + MVVM + Swift Concurrency**，以 SPM 本地包做模块化（monorepo，单 workspace 多 package），依赖方向严格单向：

```
┌────────────────────────────────────────────────────────────┐
│  App (ConnApp target)                                       │
│  组装/路由/生命周期/IAP 入口                                  │
├────────────────────────────────────────────────────────────┤
│  Feature 层（SwiftUI + ViewModel，每个 PRD 模块一个包）        │
│  FeatureDashboard  FeatureHosts  FeatureTerminal            │
│  FeatureFiles  FeatureDocker  FeatureLogs  FeatureSnippets  │
│  FeatureAI  FeatureSettings  FeatureOnboarding(演示模式)      │
├────────────────────────────────────────────────────────────┤
│  Domain 层（业务服务，无 UI 依赖）                             │
│  ConnKit：模型/仓库协议/用例                                  │
│  ConnMonitor：采集调度/解析/指标存取                           │
│  ConnRunner：片段执行/批量执行/命令流水                        │
│  ConnEntitlement：付费墙/免费限额                             │
├────────────────────────────────────────────────────────────┤
│  Infrastructure 层                                          │
│  ConnSSH：SSH 传输抽象 + Citadel 实现（终端/exec/SFTP/转发）    │
│  ConnStore：GRDB 持久化                                      │
│  ConnCrypto：密钥/Keychain/SE/E2E 加密                        │
│  ConnSync：CloudKit E2E 同步引擎（v1.1）                      │
│  ConnUI：设计系统（色彩/字体/组件，对应 设计规范.md）            │
└────────────────────────────────────────────────────────────┘
```

规则：
- Feature 只依赖 Domain + ConnUI；Domain 只依赖 Infrastructure 的**协议**；Infrastructure 互相不依赖（ConnSync 除外，可依赖 ConnCrypto/ConnStore）。
- 所有跨层交互经协议注入（构造器注入 + SwiftUI Environment），**禁止单例直取**，保证演示模式与测试可整体替换传输层。

### 1.2 关键数据流

**连接建立**：
```
用户点击主机 → HostsViewModel → ConnectionManager(actor)
  → 查 ConnectionPool 是否已有活连接（每主机复用 1 条 SSH 连接）
  → 无则 SSHTransport.connect(host, via: jumpChain)
      → 逐级建立跳板（direct-tcpip 隧道嵌套）
      → 主机指纹校验（TOFU，变更则弹警告阻断）
      → 认证（SE 密钥签名需 Face ID）
  → 成功后按需开通道：shell（终端）/ exec（采集、docker）/ sftp
```

**监控采集**（全部在前台、走已有连接）：
```
MonitorScheduler(actor)
  → 仪表盘模式：串行轮询各主机，间隔 30s，每主机一次 exec 采集脚本
  → 单机详情模式：该主机 3s 高频采集，其余暂停
  → 输出 MetricsSample → MetricsStore(GRDB) → Combine/AsyncStream 推给 UI
低电量模式：间隔 ×4；后台：全部暂停（BGAppRefresh 例外，见 §4.3）
```

**终端 IO**：
```
SwiftTerm.TerminalView ⇄ TerminalSession(actor)
  键入 → session.write(bytes) → shell channel
  channel 输出 AsyncStream<ByteBuffer> → terminal.feed(bytes)（主线程批量合帧，≤60fps）
  尺寸变化/旋转 → SIGWINCH（channel PTY resize）
```

|---|---|---|---|

| UI 参考库 | **ShipSwift**（signerlabs/ShipSwift，MIT） | 按需复制，不整包引入 | Paywall/设置页/基础组件的实现配方；复制入 `ConnUI/Vendor/ShipSwift/` 保留 LICENSE；**其组件面向 iOS 18+，复制时必须做 iOS 17 兼容适配**（API 可用性检查，必要时 `#available` 分支或替代实现，无法适配则弃用该组件）；**禁用其认证（Amplify）与追踪模块**（红线）；细则见设计规范 §10 |

> ### ⚠️ Citadel 风险框（2026-07-19 逐项核实，本文档 v1.2 新增）
>
> 立项时对 Citadel 的风险预估方向有误，实查结论如下，**S1 失败概率显著高于原估计**：
>
> | # | 事实 | 影响 |
> |---|---|---|
> | **R1** | Citadel 0.12.1 不依赖 Apple 官方 swift-nio-ssh，而依赖**个人 fork** `Wellz26/swift-nio-ssh`（PR #127，2026-04 引入）。根因是 Apple 官方版 `NIOSSHPublicKey.BackingKey` 只有 ed25519/ecdsaP256/P384/P521 四种，**完全不实现 RSA** | 一个存放私钥的安全 App，核心传输层挂在个人 fork 上；随时可能删库或停更。与 PRD §4.2「安全事故毁灭性」定位冲突 |
> | **R2** | Citadel 的 RSA 实现只有 `ssh-rsa`（SHA-1 签名），全仓库 `rsa-sha2` 零命中 | **方向与原预估相反**：老服务器（ssh-rsa）能连；反倒是 **OpenSSH 8.8+ 的新服务器用 RSA 私钥必然认证失败**（8.8 起默认禁用 ssh-rsa），且无绕过手段 |
> | **R3** | 认证方法集合只有 publickey/password/hostBased，**无 keyboard-interactive** | PRD §5.1 的 MFA（v1.1）与堡垒机 2FA/PAM 质询场景**无法实现** |
> | **R4** | 0.12.0 起平台下限从 iOS 14 抬到 **iOS 17.0**，与项目基线完全重合 | 无向下兼容余量；Citadel 若再抬版将强制项目跟进 |
> | R5 | 默认 `SSHAlgorithms()` 为空，连老服务器**必须显式传 `algorithms: .all`**。注意 API 有拼写错误 `publicKeyAlgorihtms`（少个 t） | 实现时照抄，勿"修正" |
> | R6 | `SSHHostKeyValidator.trustedKeys` 用 NIOSSH 原生类型，**不含 RSA** | RSA 主机密钥的 TOFU 固定做不到，须走 `.custom()` 自实现（§4.1 指纹库依赖此项） |
>
> **处置**：① S1 从「验证 Citadel 可用」改为「**Citadel vs libssh2 选型决策**」，见 §6；② 无论选谁，`SSHTransport` 协议层隔离从「保险」升为「必需」；③ 若选 Citadel，**必须 vendoring 该 fork** 以规避供应链风险；④ 产品层引导用户优先使用 ed25519 密钥，RSA 认证失败时给出明确诊断文案。

## 3. 数据模型（GRDB Schema v1）

命名蛇形；所有表带 `uuid TEXT PRIMARY KEY`、`created_at`、`updated_at`（ms 时间戳）；为同步预留 `sync_dirty INTEGER`、`deleted_at`（墓碑）。

```sql
-- 主机与凭据
CREATE TABLE host (
  uuid TEXT PRIMARY KEY, name TEXT NOT NULL, address TEXT NOT NULL,
  port INTEGER NOT NULL DEFAULT 22, username TEXT NOT NULL,
  auth_kind TEXT NOT NULL,            -- password | key | key_passphrase
  credential_ref TEXT,                -- Keychain 引用（见 §4.7，密文绝不入库）
  key_uuid TEXT REFERENCES ssh_key(uuid),
  jump_chain TEXT,                    -- JSON: [host_uuid,...] 逐级跳板
  group_uuid TEXT REFERENCES host_group(uuid),
  tags TEXT,                          -- JSON: ["prod","web"]
  icon TEXT, color TEXT, note TEXT,
  expire_at INTEGER,                  -- VPS 到期提醒（P2）
  sort_order INTEGER, created_at INTEGER, updated_at INTEGER,
  sync_dirty INTEGER DEFAULT 0, deleted_at INTEGER
);
CREATE TABLE host_group (uuid TEXT PRIMARY KEY, name TEXT, sort_order INTEGER, ...);
CREATE TABLE ssh_key (
  uuid TEXT PRIMARY KEY, name TEXT, kind TEXT,        -- ed25519 | rsa | se_p256
  public_key TEXT NOT NULL,                            -- OpenSSH 格式公钥
  private_ref TEXT,                                    -- Keychain/SE 引用；SE 键无可导出私钥
  ...
);
CREATE TABLE known_host (uuid TEXT PRIMARY KEY, host_pattern TEXT, key_type TEXT, fingerprint TEXT, first_seen INTEGER);

-- 片段与执行
CREATE TABLE snippet (
  uuid TEXT PRIMARY KEY, title TEXT, command TEXT,     -- 变量占位 {{name:默认值}}
  folder TEXT, pinned INTEGER, danger INTEGER,          -- danger=1 执行前强确认
  ...
);
CREATE TABLE run_history (uuid TEXT PRIMARY KEY, host_uuid TEXT, command TEXT, exit_code INTEGER, output_head TEXT, ran_at INTEGER);

-- 监控（时序，本机留存）
CREATE TABLE metric_sample (
  host_uuid TEXT, ts INTEGER, cpu REAL, mem REAL, load1 REAL,
  disk_used REAL, disk_total REAL, net_rx INTEGER, net_tx INTEGER,
  PRIMARY KEY (host_uuid, ts)
);          -- 原始 3s/30s 采样保留 48h；每小时聚合表 metric_hourly 保留 30d
CREATE TABLE probe_target (uuid TEXT PRIMARY KEY, kind TEXT, endpoint TEXT, host_uuid TEXT, last_status TEXT, last_latency_ms INTEGER, cert_expire_at INTEGER);

-- 设置与授权
CREATE TABLE app_setting (key TEXT PRIMARY KEY, value TEXT);
-- 专业版状态不入库，运行时读取 StoreKit currentEntitlements；不缓存为可放行权限
```

**Keychain 存储规范**（kSecAttrAccessibleWhenUnlockedThisDeviceOnly，同步走 E2E 不走 Keychain 同步）：
- `conn.host.<uuid>.password`、`conn.key.<uuid>.private`（PEM，含 passphrase 加密态）、`conn.ai.<provider>.apikey`、`conn.sync.masterkey`。
- Secure Enclave 密钥：`SecureEnclave.P256.Signing.PrivateKey`，`dataRepresentation` 存 Keychain，签名需 `LAContext`（Face ID）。

## 4. 核心模块设计

> 每个模块给出：职责 / 关键类型 / 实现要点 / 验收标准。Feature 层 UI 结构见原型稿，本节聚焦逻辑与边界。

### 4.1 ConnSSH — 连接引擎（v1.0 基石）

**职责**：SSH 连接生命周期、认证、跳板链、通道复用、断线重连、主机指纹信任库。

**关键类型**：
```swift
protocol SSHTransport: Sendable {            // 引擎可替换的总抽象
  func connect(_ endpoint: SSHEndpoint, auth: SSHAuth,
               hostKeyPolicy: HostKeyPolicy) async throws -> SSHSession
}
protocol SSHSession: AnyObject, Sendable {
  func openShell(term: TermSize) async throws -> ShellChannel      // PTY
  func exec(_ command: String, timeout: Duration) async throws -> ExecResult
  func execStream(_ command: String) async throws -> AsyncThrowingStream<Data, Error>
  func sftp() async throws -> SFTPClient
  func openTunnel(to target: HostPort) async throws -> SSHTunnel   // 跳板/转发共用
  var state: AsyncStream<SSHSessionState> { get }                  // connected/reconnecting/closed
}
actor ConnectionManager {                     // 全局唯一，Environment 注入
  func session(for host: Host) async throws -> SSHSession          // 池化复用
  func disconnect(host: Host) async
}
```

**实现要点**：
1. **跳板链**：`A→B→C` 用递归 `openTunnel`：连 A，A 上开到 B:22 的 direct-tcpip 通道，把该通道作为字节流喂给下一层 SSH 握手（Citadel 支持自定义 channel 上跑 SSH client；若受阻见 Spike S4 备选：本地回环 socket 中继）。每级独立凭据，失败报错需指明**卡在哪一级**。
2. **重连**：`NWPathMonitor` 网络切换或通道 EOF → 指数退避 1s/2s/4s 共 3 次；重连成功后终端提示「已重连，会话状态可能丢失（tmux 恢复见向导）」。exec 型任务不自动重放（避免重复执行副作用命令）。
3. **保活**：应用级 keepalive（每 15s `global request keepalive@openssh.com`），前台常驻；进入后台调 `beginBackgroundTask`（约 30s 宽限）后主动挂起、不做保活。
4. **指纹**：TOFU 首次入库 `known_host`；变更 → 全屏红色警告，默认阻断，需输入主机名确认才可覆盖（防降级攻击的摩擦设计）。
5. **算法兼容**：维护一张支持矩阵（文档内更新）；握手失败时给出可读诊断（「服务器仅支持 ssh-rsa/SHA-1，属于旧算法……」）并链接帮助页。
6. **危险命令拦截**在 Runner 层做（§4.6），传输层不做语义判断。

**验收标准**：
- [ ] 连接 Ubuntu 22/24、Debian 12、CentOS 7（旧算法）、Alpine、OpenWrt 各真实环境成功率与错误可读性人工验收
- [ ] 二级跳板链（含每级不同认证方式）可连通，错误能定位层级
- [ ] 飞行模式切换 Wi-Fi/蜂窝，10s 内自动恢复或给出明确失败态
- [ ] 指纹变更场景 UI 阻断有效；单元测试覆盖 known_host 读写

### 4.2 FeatureTerminal + TerminalSession — 终端（v1.0 生命线）

**职责**：SwiftTerm 桥接、会话管理（多标签）、加速键条、手势、主题、外接键盘、中文 IME。

**实现要点**：
1. `TerminalHostingView: UIViewRepresentable` 包装 `SwiftTerm.TerminalView`；数据面走 `TerminalSession(actor)`，UI 面 `TerminalViewModel(@Observable)`。输出按 16ms 合帧批量 `feed`，避免逐字节刷新掉帧。
2. **会话保持**：session 生命周期与 UI 解耦（关闭页面不断连）；每会话 scrollback ring buffer 1 万行（内存 + 退出时落盘草稿，重启可查看最后画面快照，只读）。
3. **加速键条**：`inputAccessoryView` 挂 SwiftUI（UIHostingController）；两行布局按设计稿；Ctrl 为粘滞键（点亮后下一击组合）；键位用户可编辑（存 app_setting）。
4. **中文 IME（P0 专项，Spike S2）**：处理 markedText（拼音候选阶段不下发）、候选条与键条布局冲突（键盘高度变化监听）、全角标点透传选项（默认把中文标点转 ASCII，可关）。
5. **外接键盘**：`pressesBegan` 全量捕获 Ctrl/Alt/Cmd 组合；Cmd+K 清屏、Cmd+T 新标签、Cmd+数字切换会话；iPad 上禁用系统快捷键抢占（`UIKeyCommand.wantsPriorityOverSystemBehavior`）。
6. **主题**：ANSI 16 色 + 前景/背景/光标色为一组 Theme（JSON 内置 Dracula/Solarized/Nord/GitHub 等 10 套）；字体内置 Menlo/SF Mono + 3 款 Nerd Font（打包 OFL 授权字体）。
7. **危险命令确认**：回车前正则匹配高危模式（`rm -rf /`、`mkfs`、`dd of=/dev/`、`:(){:|:&};:` 等规则表 JSON 内置可更新）+ 主机带 `prod` 标签时二次确认弹层。

**验收标准**：
- [ ] `vim`/`htop`/`tmux`/`less` 全屏应用渲染与按键正确；中文文件名/输出不豁口
- [ ] 中文输入法在 iOS 系统键盘下输入拼音→上屏全程不污染终端流
- [ ] 万行滚动 60fps（Instruments 验证）；后台切回恢复画面 ≤300ms
- [ ] 外接键盘全部声明快捷键在 iPad 实机可用

### 4.3 ConnMonitor — 监控与巡检（v1.0 差异化）

**职责**：采集调度、指标解析、时序存取、拨测、证书检查、（P2）BGAppRefresh 尽力巡检。

**实现要点**：
1. **单趟采集脚本**：一次 exec 执行拼接命令，段间用 sentinel 分隔，避免多次往返：
   ```
   echo __CONN_S1__; cat /proc/stat; echo __CONN_S2__; cat /proc/meminfo; \
   echo __CONN_S3__; cat /proc/loadavg; echo __CONN_S4__; df -kP; \
   echo __CONN_S5__; cat /proc/net/dev; echo __CONN_S6__; uptime -s 2>/dev/null; \
   echo __CONN_S7__; ps -eo pid,comm,pcpu,pmem --sort=-pcpu 2>/dev/null | head -21
   ```
   CPU 利用率需两次 /proc/stat 差分（调度器保留上次快照）。**兼容性**：BusyBox/Alpine 无 GNU ps 选项 → 解析器按能力探测降级（首次连接跑 capability probe 并缓存到 host 表）。
2. **调度策略**：仪表盘可见 → 每主机 30s；单机详情 → 3s；页面不可见即停。并发上限 4 主机同时采集（TaskGroup + semaphore）。
3. **存储**：原始样本写 `metric_sample`（48h TTL，启动时清理），每小时聚合到 `metric_hourly`（avg/max，30d）。曲线查询一律走聚合表 + 当日原始。
4. **拨测**：HTTP(S)（状态码+延迟+证书链到期日，`URLSession` + `SecTrust` 取 notAfter）、TCP 连通（Network.framework 计时）、ICMP（SimplePing）。App 打开时自动跑一轮 + 手动刷新。
5. **BGAppRefresh（P2，随 v1.5）**：注册 `BGAppRefreshTaskRequest`（earliest 30min）；唤醒后 25s 预算内串行探测「已加星标」主机的拨测目标（不开 SSH，太慢），异常发本地通知；设置页明示系统调度不可保证。
6. **安全体检（P2）**：独立 exec 脚本（sshd_config 关键项 grep、`lastb | head`、包管理器待更新计数），只读不改配置。

**验收标准**：
- [ ] Ubuntu/Debian/CentOS/Alpine 四发行版指标数值与 `top`/`free` 人工比对误差 <5%
- [ ] 仪表盘 10 主机场景电量：前台连续 10 分钟耗电 <3%（实机基准）
- [ ] 断连主机在仪表盘显示明确的灰色/错误态，不阻塞其他主机刷新
- [ ] 解析器单测覆盖：GNU/BusyBox 两套样本输出 fixture

**实际落地形态（v1.2 修订）**：采用**单个本地 SPM 包 + 多 target**，而非多个独立 package。边界约束效果完全相同（Swift 编译器同样强制 target 间依赖方向），但 Xcode 工程只需接线一次（大幅降低 pbxproj 手改风险），依赖版本集中在一个 `Package.swift`。

### 6.1 S1 结论回写（2026-07-21，环境实测）

**测试环境**：`Spikes/S1-ssh-matrix/`（Docker 7 容器，幂等可重建）。覆盖 OpenSSH 8.9/9.6/9.2/7.4 + dropbear 2026.91，端口 2201–2206。四种认证方式（密码/ed25519/RSA/带 passphrase 密钥）× 5 服务端全部实测。完整算法矩阵见 `Spikes/S1-ssh-matrix/ALGORITHMS.md`。

**核心发现（修正立项时的风险预估方向）**：

1. **「现代服务器 RSA 连不上」这个说法要拆细**：RSA **密钥本身**在 OpenSSH 8.8+ 上完全能连——现代客户端自动用 `rsa-sha2-512` 签名。被拒的只是**遗留的 ssh-rsa(SHA-1) 签名算法**。所以真正的判据不是「是否支持 RSA」，而是「**是否实现 RFC 8332 的 rsa-sha2-256/512 并遵守 server-sig-algs**」。
   - 实测：ubuntu24 的 `server-sig-algs` 不含 ssh-rsa；强制 `PubkeyAcceptedKeyTypes=ssh-rsa` 会被服务器以 "corresponding algorithm not supported" 拒绝。
   - **对 Citadel 的判决**：Citadel 的 RSA 签名前缀写死 `ssh-rsa`(SHA-1)、全仓库无 rsa-sha2，因此**用 RSA 私钥连 ubuntu22/24、debian12、dropbear 会全部认证失败**（R2 成立，但仅限 RSA 密钥）。**ed25519 对全 5 个服务端 100% 可用。**

2. **SHA-1 用户认证实际已死**：即便是配置成支持 ssh-rsa 的 CentOS 7.4，其 server-sig-algs 也只播报 rsa-sha2-*。SHA-1 只在 **host key / KEX / cipher** 层面仍有意义（仅 CentOS 7 需要 group14-sha1 KEX + CBC cipher）。

3. **跳板链（S3 提前验证）**：`host → bastion(2206) → internal(无端口)` 经 direct-tcpip 实测通过；宿主直连 internal 失败（负向对照通过）。

**引擎选型决定**：

| 判据 | 结论 |
|---|---|
| 默认密钥类型 | **ed25519**——全矩阵 100% 可用，产品应在密钥生成时默认选它 |
| RSA 支持 | 引擎必须实现 rsa-sha2-256/512；Citadel 不满足此项 |
| Citadel 是否可用 | **可用但有边界**：ed25519 全通；RSA 私钥连现代服务器失败。若用户导入 RSA 私钥连 Ubuntu22+，必须给出「建议改用 ed25519」的明确诊断 |
| CentOS 7 类老服务器 | 需要 group14-sha1 KEX + CBC cipher + ssh-rsa host key；Citadel 传 `algorithms: .all` 可覆盖 |
| keyboard-interactive | Citadel 仍不支持（R3 不变），MFA/2FA 场景待 libssh2 或自研补齐 |

**Phase 2 起步动作**：先用 Citadel 落地 ed25519 全链路（覆盖绝大多数场景），把 RSA-sha2 缺口与 keyboard-interactive 作为 `SSHTransport` 协议层下可替换/可补充的部分单列，不阻塞主线。是否引入 libssh2 取决于 RSA/MFA 用户占比，留到 Phase 2 中段依据真实需求决策。
