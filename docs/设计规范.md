## 0. 裁决规则（v1.3 确立，优先于本文其余各节）

本规范与 [prototypes/index.html](./prototypes/index.html) 曾存在 57 处不一致（8 处色值、11 处组件尺寸、以及 4pt 网格/字号比例/圆角下限的系统性偏离）。裁决规则如下：

1. **原型 CSS 实际值 > 本规范文字表述**（令牌色值、字号、圆角、间距、组件尺寸）。冲突处以原型为准，并回写本规范。
2. **原型的布局与构图** 同样为准（屏内元素排列、层级、信息密度）。
3. **例外一（触控）**：原型中视觉尺寸小于 44pt 的可点元素（如 `.key` 34px、被当按钮用的 `.pillst` 18px），**视觉尺寸照原型，点击热区用 SwiftUI `.contentShape()` 单独撑到 44×44pt**。两者不冲突，无需牺牲任一方。
4. **例外二（产品事实）**：涉及价格、权益、版本号等产品决策时以 **PRD 为准**（如买断价：PRD §8.2 定 ¥68 首发 / ¥98 原价，原型 S10 的 ¥98/¥128 为过期稿）。
5. **例外三（原型缺陷）**：原型自身的实现缺陷不构成真值（如 L15 深色令牌自引用循环），需另行补值并回写两处。

**读法换算**：原型手机屏画幅 320×660px 中，**几何值按 1:1 读作 pt**（卡片 16px = 16pt，与本规范 §4 精确吻合），**字号按 ×1.219 换算后吸附到 §3 类型比例**（9px→11pt、10.5px→13pt、12.5px→15pt、13.5px→16pt、14.5px→17pt）。

## 1. 设计语言

**关键词：星舰驾驶舱（Starship Cockpit）· 静谧未来感 · 时尚简约。**
Conn 的隐喻是"服务器的星舰驾驶舱"：深空蓝黑的底、电光蓝紫的仪表辉光、大圆角的连续曲率面板——信息像航电仪表一样一眼可读，操作像舱内开关一样明确可控。深色是主人格（OLED + 运维人群夜间审美），浅色是完整的次人格。风格基准：NeoServer 式的简洁美观 + Linear/Vercel 式的工艺密度（emil-design-eng 技能语系）；**克制**仍是底线——未来感来自材质与光，不来自装饰性动画。

三条铁律：
1. **状态先于装饰**：色彩优先编码健康状态（好/警/危），品牌蓝紫不与状态语义抢地盘——"正常"的绿色只出现在状态点等小元素上，绝不做品牌色（见 §2 用法约束）。
2. **数据用等宽**：一切数字、地址、路径、命令用 SF Mono + `tabular-nums`，杜绝跳动。
3. **单手可救火**：高频操作（重启/日志/终端）放拇指热区（屏幕下半），破坏性操作永远二段确认。

> **附注：深色 5 令牌的推导方法**（v1.3）。原型 `index.html` L15 原为 `--key:var(--key)` 一类自引用，属 CSS 循环引用，按规范作 "invalid at computed-value time" 处理，故深色下这 5 个变量**完全无值**——TabBar 底、键帽与描边、进度槽、指标环底圈、IconChip 默认底托、chevron 图标色在深色主题下均失效。补值方法：观察每个令牌在**浅色**主题下与基础色板的相对关系，把该关系镜像到深色。例如 `connBar` 浅色 `#ECEEF5` 比 `connBg #F2F3F8` 略暗，故深色下应比 `connBg #0A0C14` 略亮 → `#151A2B`；`connDim` 浅色比 `connMuted` 更淡，故深色下应比 `connMuted #8E95AC` 更暗 → `#5C6379`。

约束：
- 状态色三选一原则：一个组件内状态色只出现一种语义；红色出现即为最高优先级。
- 色彩不是唯一指示：状态点必须伴随文字或形状（●正常 ▲警告 ✕故障，见原型）。
- 深色下 `connAccent` 在 `connBg` 上对比度约 8:1，可直接做文字色；浅色必须用 `#4F58E3` 深紫版本。
- **层次手法（NeoServer 实拍校准）**：**不用外发光**。层级靠"色阶差"（卡片比背景亮约 8%）+ 卡片**顶边 1px 微光**（`rgba(255,255,255,.05)` inset，模拟玻璃质感）；主按钮仅允许极轻投影（accent @ 22%，radius ≤10）。"平面但有深度"。
- **指标专属色（数据即装饰）**：CPU = 品牌蓝紫 `connAccent`、内存 = 冰青 `connInfo`、磁盘 = 琥珀 `#F7A45C`（新增 token `connDisk`，light `#D97B2A`）、网络 = 中性灰白（流量是数字不是状态）；超阈值仍统一切 warn/crit。
- **主题唯一性**：只有深色、浅色两套主题（跟随系统 + 手动切换），不做第三种风格或用户自定义主题；终端画布两主题下恒为深色。

## 4. 布局与间距

- **4pt 网格**：间距只用 4/8/12/16/20/24/32；页面左右安全边距 16pt（iPad 20pt）。
- **圆角（一律连续曲率 `.continuous`，squircle 观感）**：卡片 16pt、列表行 14pt、按钮 12pt、图标容器 12pt、输入框 12pt、弹层顶部 20pt、状态胶囊 capsule。圆角是本设计语言的显性特征，禁止出现 <10pt 的方角容器（分隔线除外）。
- **触控目标 ≥ 44×44pt**；列表行高 ≥ 52pt；终端加速键条键高 40pt（间隙补足触区）。
- **导航**：5 Tab（仪表盘/主机/终端/命令/我的）；层级页用 push，动作用 sheet，破坏确认用 alert/confirmationDialog。
- iPad：`NavigationSplitView` 三栏，断点跟随系统 size class，不自造断点。

## 6. 动效（Motion）— 按 emil-design-eng / apple-design 技能校准

**频率决定是否动画**：高频操作（键盘触发、会话切换）**不动画**；常规弹层标准动画；首次/低频场景（首启、购买成功）可加一点仪式感。

| 场景 | 规格 |
|---|---|
| 按压反馈 | 所有可按元素 `scale(0.97)`，100–160ms，ease-out——"界面在听你说话" |
| 进场（弹层/卡片） | 强 ease-out `cubic-bezier(0.23, 1, 0.32, 1)`，150–250ms；**永不从 scale(0) 出现**，起点 ≥ scale(0.96)+opacity 0 |
| Sheet/抽屉 | iOS drawer 曲线 `cubic-bezier(0.32, 0.72, 0, 1)`，~280ms；可中断（SwiftUI spring `duration:0.4, bounce:0.1`） |
| 退场 | 一律快于进场（~0.7×时长），ease-out |
| 数字变化 | `contentTransition(.numericText())` |
| 列表首次载入 | stagger 40ms/项（仅首屏一次，不阻塞交互） |

**动效白名单**（除此以外不动）：状态点脉冲（故障态 1.2s 呼吸，`reduceMotion` 改静态高亮）、指标环首次绘制、下拉刷新、粘滞键点亮、按压反馈、弹层进出场。
**禁止**：视差、明显弹跳（bounce > 0.15）、装饰性粒子/背景动画、键盘触发动作的任何动画；一切动效尊重 `accessibilityReduceMotion`（保留透明度过渡、去除位移）。
**验收**：含动效交付必须过 `review-animations` 技能；慢速回放检查 easing 起步与 transform-origin。

## 7. 深浅色与可访问性

- 全部颜色走 token，禁止硬编码 hex 于视图代码；两套主题都必须过 4.5:1（正文）/3:1（大字/图形）对比度检查（CI 可脚本抽查 token 组合）。
- Dynamic Type：非终端区全部支持至 AX3；布局用 `ViewThatFits`/自动换行兜底。
- VoiceOver：HealthCard 聚合朗读（"web-01，正常，CPU 32%"）；终端区提供「朗读最后一行输出」动作；所有 icon-only 按钮带 `accessibilityLabel`。
- 触觉：连接成功 `.success`、故障告警 `.warning`、破坏确认 `.rigid`；设置可关。

## 8. 文案语调（UX Writing）

- 冷静、具体、给出下一步：错误 = 「发生了什么 + 怎么办」（例：`连接超时：22 端口无响应。检查防火墙或确认 sshd 正在运行 → [诊断]`）。
- 破坏性按钮写明对象：「停止 nginx-proxy」而非「确定」。
- 中文为源语言；专业名词不硬译（Docker/SSH/tmux 保留英文）；全角/半角混排规范：中英文间空格由 `Text` 自动处理，mono 区不加。

## 9. SwiftUI 落地约定

- `ConnUI` 包输出：`Color.conn*` 扩展、`Font.connData()`、`StatusPill`/`HealthCard`/`MetricGauge`/`LogLineView`/`ActionTile` 等组件 + Preview 目录（每组件双主题 Preview）。
- 组件一律 stateless（数据入参 + 事件闭包出参），状态在 Feature ViewModel。
- 原型（prototypes/index.html）是视觉验收基准：实现后逐屏与原型对比走查，偏差需在 PR 说明。

## 10. 实现参考与设计工作流

### 10.1 参考工程：ShipSwift（github.com/signerlabs/ShipSwift）

MIT 协议、iOS 18+ 的 AI 原生 SwiftUI 组件库（SWAnimation / SWChart / SWComponent / SWModule 四层，组件自包含、可独立复制）。**用法是"配方式按需复制改造"，不整包引入。**

> ⚠️ **版本适配**：Conn 部署基线为 iOS 17.0+，而 ShipSwift 面向 iOS 18+。每个复制的组件必须验证在 iOS 17 上可编译可运行——用到 iOS 18 独有 API 时做 `#available` 分支或替换实现；适配成本过高的组件直接弃用，自行按原型实现。

| 可参考 | 对应 Conn 场景 |
|---|---|
| SWModule 支付墙（StoreKit 2） | S11 Paywall 落地骨架 |
| SWModule 设置页框架 | S10 我的/设置 |
| SWComponent 基础件（输入框/警告/加载/Tab/Stepper） | 全局基础组件 |
| SWChart | 监控图表实现参考（主选仍是 Swift Charts） |
| SWAnimation | 仅取指标环绘制、状态脉冲所需的少量动效 |

**禁止吸收**（与 Conn 红线冲突）：
- 认证模块（Amplify/Cognito）——Conn 无账号体系；
- TikTok 追踪等一切数据上报模块——零遥测红线；
- Metal 装饰性背景特效（等离子体/分形云等）——违反本规范 §6 动效克制铁律。

**落地约定**：复制的代码放 `ConnUI/Vendor/ShipSwift/`，保留原 SW 前缀与 MIT LICENSE 头；对外包装层用 Conn 命名（如 `ConnPaywallView` 内部组合 SW 组件）；颜色/字体一律改接本规范 §2–§3 令牌，禁止残留 ShipSwift 默认样式。

### 10.2 设计工作流技能（本机已安装，实现时必须使用）

**A. ui-ux-pro-max**（设计系统与 UX 检查）
- 实现任何新页面/组件前，先运行该技能生成/核对设计系统基线（`--design-system -p "Conn"`），按需补查 `--domain ux`、`--stack swiftui`；
- 每次 UI 交付前必须过其 **Pre-Delivery Checklist**（正文对比度 ≥4.5:1、触控 ≥44pt、无 emoji 图标、按压反馈、`reduceMotion` 尊重等）。

**B. Emil Kowalski 设计技能组**（github.com/emilkowalski/skills，MIT，作者为 Vercel/Linear 背景的设计工程师，Sonner/Vaul 作者）

| 技能 | 用途 | 使用时机 |
|---|---|---|
| `apple-design` | Apple 设计原则与流体动效 | **最优先**：每次 UI/动效实现前对照（Conn 是 iOS 原生 App，天然对齐） |
| `emil-design-eng` | 综合设计/动画品味规则 | 组件与交互实现时的通用参考 |
| `review-animations` | 动画质量严格审查 | 每次含动效的交付前必过（指标环、状态脉冲、粘滞键、数字过渡） |
| `animation-vocabulary` | 精确的动画描述措辞 | 写动效实现说明/与 AI 协作调参时 |
| `improve-animations` | 全库动画审计 | 里程碑收尾时跑一次 |
| `find-animation-opportunities` | 发现可加动效的位置 | ⚠️ **慎用**：与本规范 §6 克制铁律冲突，仅在动效明显缺失时参考，产出需逐条对照 §6 白名单过滤 |

**冲突裁决顺序**：本规范（品牌决策：状态色分离、mono 数据、§6 动效白名单）＞ apple-design ＞ 其他技能建议。技能的价值是把 §6 允许的少数动效做到工艺级，而不是增加动效数量。
